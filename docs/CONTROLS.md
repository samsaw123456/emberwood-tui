# Physical terminal control audit

The same complete **177-row inventory passed again on v1.0.2** on Linux x64 and
both macOS architectures in [CI run 43738439037](https://github.com/samsaw123456/emberwood-tui/actions/runs/43738439037).
Every saved full/focused snapshot on those platforms was independently replayed
from retained raw ANSI. The table below preserves its original capture paths;
v1.0.2 evidence lives under `build/release-1.0.2/ci`. The [verification record](VERIFICATION.md)
identifies the executable, supplemental physical cases, visual-review scope and
platform limits. No old campaign run is relabelled as a new playthrough.

Generated by `python3 tools/ansi_audit.py` against a running tui4j process in a real PTY. Every listed key is sent as ANSI input. Before/during/after PNGs are reconstructed from completed ANSI paints; each snapshot records its exact character offset in the retained raw stream. The decoder honors primary/alternate screen switching. Raw ANSI and state records remain under `build/quality-review/ansi-audit-final`. The fixture host sets starting states; it does not call input handlers directly.

Steering is intentionally latched: ordinary ANSI terminals send key presses but no releases. A/D or arrows select direction, S/Down stops; X replaces modifier-only Shift. Ctrl+Z pauses without toggling resume; P/Esc resumes. Both terminal-generated suspend signals and literal Ctrl+Z bytes are checked. Binding letters denote unshifted lowercase keys. No mouse, controller, touch, manual camera keys, uppercase letter aliases, or key-release protocol is implemented. Terminal font and audio-device behavior require separate host checks.
